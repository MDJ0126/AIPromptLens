# 게임 프롬프트
게임 개발의 기술·개념·도구를 찾고, 필요한 표현을 프롬프트로 조합하는 사전입니다.

## 실행
Node.js 18 이상에서 node server.js 를 실행하고 http://localhost:4173 을 여세요.
별도 패키지 설치는 필요하지 않습니다. 종료는 Ctrl+C입니다.
다른 포트를 사용하려면 PORT 환경 변수를 설정하세요.

## 기능
- 밝은/어두운 테마, 19개 카테고리, 340개 게시물
- 동작 예시의 자동 애니메이션과 일반 용어의 정적 정의 카드
- 영문 약어·별칭 검색, 입력 중 추천어 목록과 독립 스크롤
- 게시물별 마지막 확인일, 확인 범위, 출처·버전 및 엔진 실행 미검증 표시
- 게임 설명의 단어를 등록된 표현과 연결해 기술 후보와 이유 제안
- 한글·영문 용어와 설명 검색, 게임 유형 필터
- 개념 설명 및 AI 요청 예시
- 표현 저장, 선택 조합, 한국어·영어 프롬프트, 클립보드 복사
- 브라우저 로컬 저장, 모바일 레이아웃, 동작 줄이기 설정 대응

영어 모드에서도 사용자가 입력한 게임 설명은 그대로 유지합니다.
예시는 개념을 단순화한 도식이며 실제 게임 화면이나 엔진 구현 결과가 아닙니다.
로그인·클라우드 저장·AI 모델 호출은 포함되지 않습니다.

## GitHub Pages 운영
1. 파일을 GitHub 저장소 main 브랜치에 커밋·푸시하세요.
2. 저장소 Settings → Pages → Build and deployment → Source에서 GitHub Actions를 선택하세요.
3. Actions에서 Deploy PromptLens to GitHub Pages를 실행하세요. 이후 main 푸시 시 자동으로 검사하고 배포합니다.
4. 완료된 워크플로의 deployment URL에서 접속하세요.

계정·저장소 설정에 따라 Pages 사용 가능 여부와 사이트 주소가 달라질 수 있습니다.
배포 성공 전에는 공개 운영이 완료된 것으로 간주하지 않습니다.

## 검증
node --test tests/*.test.js 로 카탈로그 및 검색·선택·프롬프트·저장 동작을 검증합니다.

## 참고
자료 출처는 게시물별 참고 자료에서 확인할 수 있습니다. 조사 메모는 로컬 .local 폴더의 Markdown 파일로 관리하며 공개 배포와 Git 업로드에서 제외합니다.

도식과 요청 예시는 이 프로젝트에서 작성했습니다.


추천은 브라우저에서 동작하는 단어 연결 규칙입니다. AI 의미 분석이나 확정된 필수 기술 목록이 아니며, 등록되지 않은 기술은 제안하지 않습니다. 후보는 자동으로 선택하지 않고 사용자가 직접 담습니다.
일반 용어 카드는 기술 동작을 재현한 애니메이션이 아닙니다.

## 게시물 관리
게시물의 원본은 site/articles/*.md 입니다. 각 파일의 맨 위 JSON 형태의 front matter에서 카드 제목·분류·설명·요청 문장을 관리하고 본문에서 구조·Unity C#·Unreal C++·설정·검증 상태를 관리합니다.
예: site/articles/hit.md, site/articles/coyote.md

본문만 수정하면 페이지를 새로고침한 뒤 상세 화면을 다시 열어 확인할 수 있습니다.
제목·분류 등 메타데이터를 수정했다면 node scripts/build-content.js 를 실행해 catalog.js를 갱신하세요.
catalog.js의 terms 배열은 생성 결과이므로 직접 수정하지 마세요.
새 게시물에는 고유 id, slug, 분류·장르 및 확인 날짜·범위·출처·이력이 필요합니다. 구현 게시물에는 Unity/Unreal 섹션이 필요하고, kind: concept 게시물은 기본 정의와 비교 설명을 작성합니다. 새 애니메이션과 프롬프트 추천 규칙은 별도로 등록해야 합니다.

예제는 엔진별로 구조를 보여주는 최소 코드입니다. 엔진 컴파일·실행은 이 저장소에서 검증하지 않았습니다.
Unity는 게시물마다 고유한 MonoBehaviour 클래스 이름을 사용합니다. Unreal은 프로젝트 클래스의 멤버 코드이며 클래스 선언과 연결은 별도로 필요합니다.

## 개념 게시물
kind: concept 게시물은 코드를 필수로 요구하지 않습니다. 핵심 구조, 개념 설명, 비교와 선택, 활용 상황, 확인할 질문, 도식의 한계와 참고 자료를 Markdown에 작성합니다. 상세 화면에서는 엔진 탭 대신 개념 설명을 표시합니다. 원리·설계 카테고리에 베이크 조명, 스크린 스페이스 반사, 소리 차폐를 추가했습니다.


## 사전 확장 확인 범위

2026-10-14에 후보 227개를 신규 정의 207개와 기존 용어 별칭 20개로 처리했습니다. 확인은 기본 정의와 적용 범위의 문서 대조이며, 세부 설정 전체와 엔진 실행을 검증했다는 뜻은 아닙니다. Unity 2018.4 같은 이전 버전 자료는 해당 버전을 표시합니다. 로컬 상세 기록은 .local/audit/전체후보-검토기록.md에 보관합니다.

## 게시물 이미지와 디자인

큰 소개 영역을 제거하고 검색 중심의 게임 개발 자료실 디자인을 사용합니다. 각 게시물 이미지는 site/covers/{slug}.svg에 별도 파일로 관리합니다. 이미지들은 기술 주제에 맞는 시각적 은유이며 엔진 스크린샷이나 정확한 처리 과정의 증명이 아닙니다. 공통 시각 스타일을 사용하며 기존 동작 도식은 인라인 SVG로 자동 재생합니다. 일반 정의와 반복 단계 카드에는 정적 일러스트를 사용합니다.

이미지 생성 코드: site/covers.js. 재생성: node scripts/build-covers.js. 콘텐츠 변경 후 이미지도 재생성하고 node scripts/build-covers.js --check로 확인하세요.

## 오늘의 추천과 에셋 이미지

검색창 위에서 한국 시간 자정 기준으로 매일 다른 게시물 하나를 추천합니다. 추천을 누르면 게시물 상세 화면을 엽니다. 에셋·패키지 24개는 site/asset-art.js의 게시물별 장면으로 관리합니다. 다른 분야는 기존 시각적 은유와 동작 도식을 사용하며, 파일이 다르다는 이유만으로 모든 그림을 독립적으로 제작했다고 설명하지 않습니다.
